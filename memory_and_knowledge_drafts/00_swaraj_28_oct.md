# Swaraj's corrections, 28 October 2026 (governing)

Status: these override any audit and any earlier draft. Quoted from his message, lightly cleaned.

1. Identity is a unique ID, not a channel address.
   "It won't get a WhatsApp number, some customer ID, because the same ID will have the WhatsApp number, the email addresses, etc., across multiple consumer channels. So the WhatsApp number in itself is a dumb idea." "It is some sort of a unique ID, not a WhatsApp number."

2. Memory's job is context engineering, not decision making.
   "The decision of whether to route or not goes to the conversation manager. The only responsibility of the memory and knowledge layer is to create a subset of the vast knowledge sea and create a subject and present that in that context. Its main purpose is context engineering, not decision making. Why is it crossing boundaries? Why is it crossing responsibilities?"

3. Retrieval must happen before anything is compared; a person may have thousands of finished situations.
   "He might have 10,000 of those. How will it understand which are those?" "There should be some retrieval here at this point. In the fixed part, there should be some retrieval mechanism before the thinking gets activated. Or maybe the thinking part has some retrieval mechanism."

4. Fixed code is not a hero. It has hard limits. Name the event, its structure, the parameter it reads.
   "Stop making the fixed code a hero. The fixed code is not a hero. Think of it in more of a software terms and a product. And the code cannot do the things that you are imagining."
   "What is the signal it is getting? What is the parameter it is observing the whole loop? How is it getting that thing? What is the event like? How is the event structure? Is it even possible in software?"
   "The fixed code of memory and knowledge layer that works with conversation manager will not work with situation worker. Both of them will have different fixed code components, and which will do very limiting jobs. Rest has to be done with the AI part."

5. Skills are not assumed. Default agent behaviour first.
   "Not everything has a skill. We only have tools. The skill is because there is a particular process I want to follow when I want to have the agent do deep research. Otherwise, it will just try and figure out everything."
   "If there is a default way our agent works and the business wants it to work in a different way, then they will put some skills, some business rules there, which will obviously be surfaced by the memory layer."

6. Method: engineer from fundamentals; scenarios are test cases.
   "You engineer the solution based on the fundamentals that are required, and then you use the Arjun situation and other situations, like the Priya situation, to test your concept and your architecture by walking through and hypothesize. If that is failing, then you go back to the drawing board and you revise your engineering. These are test cases, these are not engineering cases."
   "Read the three-level framework. Consider it as a particular product itself, which fits into this. Memory and knowledge layer is an agency within the agency called Tend. Take it through Level 1 and Level 2."
   "Answer all the engineering questions... basic engineering plausibility, feasibility analysis."

7. Authority.
   "Keep everything that I've said in all my messages so far, and if the technical audits, the readability audits contradict them, throw them out. I am the boss here."

8. Readability: plain words. "What does 'the note points at a past purchase' even mean?" — never use phrases whose mechanism is not spelled out.
