On 2026-11-04, asking what a column called `state` meant: "naming everything has to be very product oriented, because technical naming is fine, but I will not be able to understand and make sense of it a lot of time. It's fine if the name is long or something, as long as it follows the doesn't break the technical convention."

**Why:** he reads the code and the plans himself, and a name he must decode stops him. It repeats his earlier rule that names must say what a thing does. He also said not to Indianize names: Tend is a global product.

**How to apply:** in lessons, plans, tables, columns, indexes and modules, use names like `where_the_work_stands` and `find_a_persons_open_situations`, in the language's normal case style. Related: [[feedback-loops-from-product-stages]], [[project-situation-record-rulings]].
