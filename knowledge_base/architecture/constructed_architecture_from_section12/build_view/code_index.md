## The build view (used in `overview.md` and the ten part files)

**Notes for this folder.**
- The build view adds no rule (the method, Section 12, build view). Every rule in these files repeats a rule from another view, and carries that view's code and status. Where a part file sorts an existing rule under a kind of situation, the row is the existing one.
- Each part file answers the seventeen part-file questions, in order (decided 2026-10-17), and has one row per kind of situation (fifteen). "Not involved beyond the common path" means the part does only what it does in the common walk.
- The conversation manager's file covers its own work only: intake, routing, the update decision, and completed. The situation worker and the communication layer have their own files, though both sit inside the conversation manager (decided by the owner, 2026-10-10).
- Acceptance lines ("How do we know it is built correctly?") restate existing rules as behaviour someone can observe. They add no rule.

- Audit round 1 (2026-10-21), recorded judgments.
