# How this folder was built

This file points to where the history of this folder is kept, and gives the order the folder was written in.

The full history is in [the construction record](../../construction_record.md), entry 21. It holds, in order:
- the decisions the project owner — the person designing Tend — made while this folder was planned: its layout, the five status words, the fifteen kinds of situation, the part-file shape, the two audits, and the project owner's description, on 2026-10-17, of how the status-check service waits;
- the progress of each file, with its key choices, what each audit found, and which findings were rejected and why;
- the project owner's instruction of 2026-10-21 to finish this folder without stopping to ask, and every call made under that instruction;
- the project owner's answers of 2026-10-22 to the seven blocking questions, their acceptance of every other recommendation, and every point settled that day under their instruction.

The calls made under that instruction are also listed in [the decisions register](decisions_register.md), part 3; the points settled on 2026-10-22, in part 4.

## The order the folder was written in

1. The responsibility view: ten topic files, then a summary of all twenty-two responsibilities.
2. The boundary view: the ten parts.
3. The interaction view: twenty-three interactions.
4. The behaviour view: the common path, then one file for each of the fifteen kinds of situation.
5. The state view: every record, its writer, and its life.
6. The constraint view: the rules that always hold.
7. The decision view: eighteen decisions on 2026-10-21; twenty-five since 2026-10-22.
8. The traceability view: the chain from source to decision.
9. The build view: the overview, then one file for each of the ten parts.
10. This checking folder.
11. On 2026-10-21, after the folder was first finished: the analysis of the seven blocking questions, [blocking_questions.md](blocking_questions.md).
12. On 2026-10-22: the seven answers, and every point settled that day, applied to the design first — the decisions, the parts, the records, the rules, and the interactions — then to every file that repeats them: the behaviour view, the responsibility view, the build view, the traceability view, and this folder. Then the full audit of every file against the knowledge base, a verification round of the files the fixes had changed, and the completion record written again. The verification round's findings, and the ones rejected, are in the audit record.

Each file was audited twice. The checking folder had two rounds: a full first round of both audits, then a narrow technical round. The order of the views on 2026-10-21 is the order above; the record gives each file's rounds, not the exact hour. The build view and this folder had their audits last; the [audit record](audit_record.md) gives their results. Where a later view found an error in an earlier one, the earlier file was corrected and audited again. <!-- method: two audits per file -->

The design files written before this folder sit in [the architecture folder](../../). They are the foundation this folder was checked against; nothing here is copied from them.
