# The conflict register

This register lists the places where two written sources disagreed. For each one, it says what each side says, how the conflict was settled, and the status that leaves. Nothing is chosen silently: where a later instruction wins, the earlier line is kept here, so it can be corrected where it sits. <!-- Section 10: decisions in force -->

The earlier design files named below sit in the folder above this one: the [responsibility model](../../section_6_responsibility_model.md), the [boundary model](../../section_7_boundary_model.md), the [interaction model](../../section_8_interaction_model.md), the [reconciliation](../../section_10_reconciliation.md), the [decision records](../../section_11_decision_records.md), the [stabilization](../../section_11_stabilization.md), and the [construction record](../../construction_record.md). "The business's answers" are the business's own written answers to the engineering questions.

**What changed on 2026-10-22.** Fifteen conflicts were waiting for the project owner (the person designing Tend, not the business owner). On 2026-10-22 the project owner answered the seven blocking questions and asked for the smaller questions to be settled in the way that best fits. Every conflict in section 1 is now settled, and says how. <!-- decided by the owner, 2026-10-22; settled 2026-10-22: the open conflicts -->

## How a conflict is closed

A conflict closes when the project owner answers it, or when it is settled under their instruction. The answer is written in the construction record, the governing line is kept, and every file that repeats the point is changed to match. An earlier line outside this folder closes when it is corrected where it sits. <!-- method: change after completion -->
