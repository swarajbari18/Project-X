## The nine, inventoried

1. **Artifact-first information architecture** — Problem: ten people reached, ten situations exist; the owner must see each at a glance without opening ten conversations. L2: Business View & Ownership (artifacts = the business's primary view) + Journey & Lifecycle (links discovered later, journeys derived). Canon: signifier honesty (A1), H6 recognition, conceptual model (A5), personality (p.20). Alternatives discovered: situations-primary with journeys grouped in view · journeys-primary with situations nested · one artifact shape, context-switched faces. Open: card/row/panel defaults per surface; journey-grouping render rules; gate-enforced lifecycle words.
2. **Cross-situation views** — aggregation / filter / search / triage; owner wants exceptions and decisions, not narration. L2: Memory & Knowledge (hard filters before semantic ranking) + Journey linking. Canon: exception-first (Blocked→Changed→Waiting→Quiet), inverted pyramid, small multiples, progressive disclosure. Open: default views; grouping axes (actor/journey/urgency/staleness); search behavior across situations.
3. **Per-role surfaces** — owner dashboard · employee operational views · customer/prospect plain-language status · partner operational context. Same situation model, different cuts. Open: dialects vs one voice; how richness thins per role without forking the truth.
4. **Proactive vs pull (notification discipline)** — communicate only when the silence costs more; wait when premature/misleading. L2: Communication (the ten purposes; wait vs ask rules) + Business View attention rules. Canon: restraint-as-confidence, H1 visibility, calm-can-stretch. Open: which events push; batching windows; per-actor quiet hours.
5. **The situation/journey narrative view** — message → found → did → told → next; evidence pinned per step; honest endings spoken (answered/deferred/escalated/declared-unanswerable). L2: Explainability (viewer-dependent rendering: timeline for humans, graph/detail for builders; reconstruction as view). Open: narrative shape; evidence attachment; ending vocabulary rendering.
6. **Design language spec** — Module 7's tokens frozen: type, spacing, shade, elevation, motion, state vocabularies. The positive vocabulary (not the blacklist). Open: freeze point; token ownership; per-role thinning rules.
7. **Landing page, setup, onboarding** — honest promise (and not-promise); setup (channels, authority ranges, journey shapes); onboarding that installs the artifact-first model (Advance Organizer, help-as-a-moment) AND the visceral pairing (conditioning installation). L2: Product Vision "configuration, not core." Open: promise wording; minimum setup before Tend can act; act-one competency.
8. **The design ideation loop** — meta: how this pillar's output gets produced. Runnable form: `skills/product-design-loop/SKILL.md` (TEACH/PLAN, two surfaces, checklist-first critique, both-side proxies); factory's AI-first-pass included. Open: the skill's home; one loop or two for Tend's production cycle.
9. **The anti-"AI-slop" blacklist** — violations named by violated law + detectability + the category each slop type impersonates; quiet-by-default the unifying charge. Handoff candidates: hash gradients, sparkle icons, fake testimonials, neon gradients, rainbow colors, heavy drop shadows, missing privacy policy, stock-photo heroes, vague "AI-powered" claims, chat-everywhere-default. Open: knockouts vs degradations; the gradient question; decorative wait-matter; each item ruled, never adopted blindly.

**State words thread through all nine** (WAITING / ACTIVE / BLOCKED / RESOLVED + asked / answered / deferred / escalated / declared-unanswerable): one vocabulary, two perceivers — human crops and machine gates alike.
